● Here's the equivalent of the tutorial's command:

  Your ! commands run in Git Bash, which uses Mac-style syntax, so only the
  folder changes: Scripts instead of bin.

  The catch is that each ! command runs in a fresh shell, so the activation is
  lost as soon as that command finishes. You have two ways around that:

  1. Chain activation with the command you actually want:
  ! source venv/Scripts/activate && pip install flask
  2. Call the venv's tools directly (simpler):
  ! venv/Scripts/pip install flask
  ! venv/Scripts/python app.py

  Either way, packages go into your venv. Whenever the tutorial says pip ... or
  python ... after activating, use venv/Scripts/pip ... or venv/Scripts/python 
  ... here instead.

❯ what does this project do?                                                    

  Ran 1 shell command (ctrl+o to expand)

● Spendly is a personal expense tracker web app built with Flask (Python) and
  SQLite. It's a step-by-step tutorial project: you start from a skeleton and
  build the features yourself.

  What the finished app does
  - You sign up and log in with your own account.
  - You add expenses with an amount (in ₹), category (Food, Bills, Transport,
    Health and so on), date and description.
  - You can edit and delete expenses.
  - It shows category breakdowns and monthly summaries of your spending.
  - You can filter expenses by date range, such as last week, last month or a
    custom period.

  What exists right now
  - Working pages: the landing page, plus the register and login pages. The
    register and login forms don't do anything yet.
  - Placeholders: /logout, /profile and the add/edit/delete expense routes only
    show text like "coming in Step 7".
  - Database: database/db.py is empty apart from comments. Step 1 asks you to
    write get_db(), init_db() and seed_db() there.

  The tutorial's order
  1. Database setup
  2. Registration
  3. Logout
  4. Profile page
  5. and 6. Not named in the code yet
  6. Add an expense
  7. Edit an expense
  8. Delete an expense

  Steps 2–6 are partly inferred: only Steps 1, 3, 4, 7, 8 and 9 are labelled in
  the code. Pytest and pytest-flask are in requirements.txt, so you'll probably
  write tests along the way too.

● The stack is deliberately small, with no frontend frameworks or ORMs.

  Backend
  - Python runs the app (your venv has Python 3).
  - Flask 3.1.3 is the web framework; it handles routing and page rendering in
    app.py.
  - Werkzeug 3.1.6 is the toolkit underneath Flask. It also provides password
    hashing (generate_password_hash and check_password_hash), which the
    registration and login steps will probably use.

  Database
  - SQLite, accessed through Python's built-in sqlite3 module, with no ORM like
    SQLAlchemy. The data will live in expense_tracker.db, which .gitignore
    already excludes.

  Frontend
  - Jinja2 templates: every page extends base.html.
  - Plain CSS: about 530 lines of hand-written styles in static/css/style.css,
    with no Bootstrap or Tailwind.
  - Plain JavaScript: static/js/main.js is just a placeholder comment for now.
  - Google Fonts: DM Serif Display for headings and DM Sans for body text.

  Testing
  - pytest 8.3.5 and pytest-flask 1.3.0 are installed for testing the Flask
    routes.

  Tooling
  - A venv for dependencies, Git for version control, and GitHub for hosting the
    code.

❯ explain the project structure to me                                           

  Ran 1 shell command (ctrl+o to expand)

● expense-tracker/
  ├── app.py                  ← entry point: Flask app + all routes
  ├── requirements.txt        ← Python dependencies
  ├── .gitignore              ← files Git should ignore
  ├── database/
  │   ├── __init__.py         ← makes "database" an importable package
  │   └── db.py               ← database helpers (empty — you write this in Step
  1)
  ├── templates/              ← HTML pages (Jinja2)
  │   ├── base.html           ← shared layout: navbar, footer, CSS/JS links
  │   ├── landing.html        ← home page
  │   ├── register.html       ← sign-up form
  │   └── login.html          ← sign-in form
  ├── static/                 ← files sent to the browser as-is
  │   ├── css/style.css       ← all styling
  │   └── js/main.js          ← client-side JS (empty for now)
  └── venv/                   ← your virtual environment (not in Git)

  How the pieces connect

  1. A browser asks for a URL such as /login.
  2. In app.py, @app.route("/login") maps that URL to the login() function.
  3. That function calls render_template("login.html"), and Flask looks the file
     up in templates/.
  4. login.html starts with {% extends "base.html" %}, so it's placed inside the
     shared layout (navbar, footer, fonts, CSS).
  5. The layout loads static/css/style.css and static/js/main.js with
     url_for('static', ...).

  Flask finds templates/ and static/ by name automatically, so you don't
  configure those paths anywhere.

  Where your code will go
  - database/db.py: connecting to SQLite, creating tables and adding sample
    data. app.py will import from here.
  - app.py: route logic, such as reading form data, saving to the database and
    handling login sessions. The placeholder routes get replaced step by step.
  - templates/: new pages as you build them, such as profile, the expense list
    and the add/edit expense forms.
  - main.js: client-side behaviour, if later steps need any.

  One thing to expect: the register and login forms already submit with
  method="POST", but their routes in app.py only accept GET requests so far.
  Submitting either form right now gives a 405 Method Not Allowed error. That's
  normal at this stage; you'll fix it when you build registration and login.
